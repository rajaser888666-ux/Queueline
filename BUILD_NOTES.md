## Phase 0 — spec and market check
- canivibecodeit (`/workspace/work/civci/data/apps/getwaitlist.json`): verdict YES, "one sitting", $15/mo (GetWaitlist Basic; no free tier for accounts created after 2025-06-12; Advanced $50, Pro $250). coreLoopDIY and requirements are empty in the data; the curated `prompt` is the spec: drop-in HTML form, dedupe by email, honeypot, IP rate limit, position + `?ref=CODE` link, each referral moves you up 5 (base_position − 5 × referrals), /admin with count, inline-SVG growth chart, CSV export, delete per row, no third-party services.
- whatYouLose: their referral-widget templates, built-in email blasts, tuned spam filtering. rejectedAlternatives: LaunchList Free (referrals stop at 100 signups), Prefinery (trial; $39/mo), Waitlister Free (100 emails, referrals from $19/mo).
- Web check (2026-10-11): canivibecodeit says "no free alternatives", but several **self-hosted open-source** options do exist: Refqueue (MIT, Next.js + Supabase, refqueue.com), zexiro/waitloop (AGPL, Postgres), Martello-Systems/launchpad, earlypass (BSL), zaidazmi/open-waitlist (Supabase + Resend), d4mr/0list (Cloudflare D1), iannil/v-waitlist (Upstash Redis). Hosted free tiers cap at 100–200 signups (WaitForge, Waitspot, WaitlistQ, LaunchList v2 "free to start").
- Differentiation we built for: **hosted and multi-tenant with zero setup** — no database to provision, no account, no Supabase/Redis/SMTP signup; admin by private link; one script tag; no signup cap at the product level; fraud rule (same-network referrals don't count) and transparent scoring shown to the admin.

## Phase 2 — Build
- Name: **Queueline**. Design: off-white/ink, one deep-green accent (#0f5c4d), system font, tabular numerals, plain tables and panels; no gradients, glow, eyebrow labels, decorative dots or subheads under every heading.
- Storage: **Vercel Blob, private store** `queueline-store` = store_fuS1AFDQeScLtnUT (iad1), created via `POST /v1/storage/stores/blob` with `access:"private"`, connected via `POST /v1/storage/stores/{id}/connections` (sets BLOB_READ_WRITE_TOKEN on the project). A first public store (store_VYILCVkg9YInM1vO) was deleted because signups are PII.
  - Model: one JSON ledger per waitlist at `wl/{id}.json` (config + admin token hash + signups array). Create = `put(allowOverwrite:false)` (exclusive). Every mutation = `get(useCache:false)` → mutate → `put(ifMatch: etag)`; on `BlobPreconditionFailedError` retry with jitter (6 attempts) → no lost writes under concurrency. Line order = append (commit) order, not timestamps (fixed a real race found by the concurrency test).
  - Why one object: Hobby Blob includes only **2,000 advanced ops (put/list) and 10,000 simple ops per month**; exceeding blocks Blob for 30 days (no charge). One put per signup, no list() calls, 15 s in-memory cache for public reads.
- Features: create waitlist (name, owner email, description, spots per referral, optional landing-page share URL; honeypot); private admin link `/admin/{id}#k=TOKEN` (token in URL fragment so it never hits logs/referrers; sha256 stored; timing-safe compare); hosted page `/w/{id}` (+ `?ref=`, `?me=statuskey`); embed `/embed.js` (`data-waitlist`, `data-target`, `data-button`, `data-accent`, `data-placeholder`), CORS `*`; signup returns position, total, referral link, referral count, share buttons (X, WhatsApp, LinkedIn, email); returning visitors see live position (status key in localStorage); admitted people see "You're in."
- Scoring: position among waiting = rank by (join order − points × valid referrals), ties to earlier joiner. Valid referral = referee not removed and from a different IP hash than the referrer.
- Bot/abuse: honeypot (silent fake success), min 600 ms form time (widget waits it out automatically), per-instance burst limit 12/min/IP, durable per-waitlist cap 5 signups/IP/hour (stored salted IP hashes), small disposable-domain blocklist, removed emails can't rejoin, 10k signups/list cap.
- Admin: stats (signups, waiting, admitted, referrals), 14-day inline-SVG bar chart, sortable/searchable/filterable table with position, referrals, referred-by, join time, status; Offer spot / Undo / Remove / Restore per row; "Offer spots to the next N"; mailto "Email" for admitted; CSV export (BOM, formula-injection guard); settings (name, description, points, share URL, leaderboard, hide count).
- Email sending: not included (no free sender without a third-party signup). Shown as a limit in UI and on landing page.
- Test hook: `QL_TEST_KEY` env + `x-ql-test-key`/`x-ql-test-ip` headers let tests simulate distinct visitors on Vercel (all sandbox traffic shares one IP). Inert unless the secret matches.

## Known limits
- **Vercel Hobby Blob quota**: 2,000 advanced ops (≈ signups + admin actions + waitlist creations) and 10,000 simple ops (reads) per month across all waitlists; past that Blob is blocked for 30 days (no charge). Roughly 1,500–1,800 signups/month in practice. Upgrading the Vercel plan or swapping the driver (e.g. Postgres) lifts it; the store interface is one file.
- One JSON object per waitlist, 10,000-signup cap per list; every signup rewrites it (fine to a few thousand; latency grows with size).
- **No email sending** (no free sender without a third-party signup): no confirmation/verification emails, no blasts. Admin gets mailto buttons and CSV export.
- No email verification, so referrals count on signup (not on confirmed email). Fraud controls are basic: honeypot, 600 ms minimum, per-IP caps, same-network referral rule, small disposable-domain list. No captcha.
- No accounts: losing the admin link loses access (it's also kept in the creator's browser localStorage/sessionStorage). No admin-link rotation or waitlist deletion UI yet.
- No custom domains, branding removal, custom fields/questions, webhooks/Zapier, analytics by country/device, leaderboard rewards tiers, multi-user teams.
- Public waitlist info (name, description, count, masked leaderboard) is cached up to 15 s per server instance.
